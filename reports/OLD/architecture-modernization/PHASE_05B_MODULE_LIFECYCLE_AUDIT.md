## Ownership and bounded correction

| Resource | Owner / treatment |
|---|---|
| RewardService and dirty UUID tracking | RewardModule creates a fresh service per activation; only this owner's tracking is cleared |
| RewardListener | RewardModule; one actual LOWEST PlayerQuitEvent handler, flushed before Player's NORMAL unload |
| 20-tick synchronous timer | RewardModule; exact handle cancelled, callback additionally gated by active state and captured service identity |
| EconomyService / PlayerService | Borrowed from their modules during each enable; never stopped, cleared, replaced or saved via a new policy by Reward cleanup |
| Player YAML / wallet / profile | Existing Player repository and domain commit boundary; no Reward file/schema or new writer |
| Plugin/server/logger | Borrowed Paper boundaries; no command descriptors, observer subscriptions or menus exist in this pilot |

The unchanged public constructor delegates to a package-local three-stage checkpoint seam with a production no-op. Checkpoints follow actual listener registration, actual acquired task and runtime-field publication. Dependency acquisition, construction, external effects, publication and final log are in one protected startup sequence. The public getter stays closed until success; explicit active/enabling/cleaning guards prevent duplicate/reentrant acquisition and lifecycle changes during cleanup.

One private cleanup path serves failed startup and disable. Independent boundaries attempt timer cancellation, the normal-disable pending flush, listener unregister and own dirty tracking release. Failed startup does not manufacture a profile save. Disable retains the established cancel → flush → unregister → clear order and Player shutdown fallback, even if an earlier operation throws. The exact original startup exception is rethrown; cleanup failures carry resource context as suppressed causes. Ordinary disable surfaces its aggregate through the unchanged ModuleManager contract.

A private cleanup record retains uncertain releases after refusal. Public runtime fields are cleared and inactive even when an external API refuses release; subsequent enable must reconcile that record before acquiring new services/listeners/tasks. A permanently refusing cancellation or HandlerList removal is reported, not claimed successful. Retrying disable can finish it. An uncancelled callback cannot reach a new activation: its captured RewardService must still equal the active service. This is module-local state, not a transaction engine, service locator or second registry.

Existing persistence policy is explicit: ordinary save failures retain coins and dirty UUIDs for retry; normal shutdown tries the current aggregate flush and eventually clears own tracking while leaving Player's later save fallback intact. A clean lifecycle without pending mutations leaves profile bytes unchanged. A dirty shutdown intentionally writes pending rewards; claiming all cleanup is byte-inert would be incorrect for this owner. Explicit old Java service references are not revoked.
